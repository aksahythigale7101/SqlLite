1. Primary Key
2. Foreign Key

3. Unique Key ex-->Email VARCHAR(100) UNIQUE
4. Composite Key-->Two or more columns together uniquely identify a row.
                example-->(PRIMARY KEY (StudentId, CourseId))
5. Candidate Key -->Understand which columns could potentially be a Primary Key.
                example-->EmployeeId → unique
                          Email      → unique
                          Phone      → unique
                 All could potentially identify an employee, so they are candidate keys. One is selected as the Primary Key.
6. Alternate Key-->Candidate key that was not selected as the Primary Key.
               example -->EmployeeId → Primary Key
                          Email      → Alternate Key
                          Phone      → Alternate Key

1. Inner  Join ----->फक्त दोन्ही tables मध्ये matching records असतील तेच records मिळतात.
                  Employee              Department
   │                       │
   │       MATCH           │
   └─────────┬─────────────┘
             ↓
       INNER JOIN
             ↓
      Only matching rows
----------->INNER JOIN returns only the rows that have matching values in both tables.                


2.Left Join ------>Left table मधील सर्व records घ्या, आणि right table मध्ये match असेल तर त्याचा data घ्या.

3.Right Join ----->Right table  मधील सर्व records आणा.

4.FULL OUTER JOIN----->Left table चे सर्व records + Right table चे सर्व records.
            LEFT table
                 +
            RIGHT table
                 +
             Matching

5.Self Join---->Same table ला स्वतःसोबत JOIN करणे = SELF JOIN.
Example:   
EmployeeId | Name   | DepartmentId | ManagerId
-----------+--------+--------------+----------
101        | Akshay | 1            | NULL
102        | Rahul  | 1            | 101
103        | Amit   | 1            | 101
104        | Sneha  | 2            | 102        
                   
Question -----> Employee आणि त्याचा Manager यांची names दाखवा.
Ans------>Query Is self Join 
     SELECT E.Name AS EmployeeName,M.Name AS ManagerName FROM Employee E LEFT JOIN Employee M ON E.ManagerId = M.EmployeeId;

Result:

EmployeeName | ManagerName
-------------+------------
Akshay       | NULL
Rahul        | Akshay
Amit         | Akshay
Sneha        | Rahul
    
    
Question----> using another talbe and make self join 
SELECT E.Name AS EmployeeName,M.Name AS ManagerName,D.DepartmentName FROM Employee E LEFT JOIN Employee M
                           ON E.ManagerId = M.EmployeeId LEFT JOIN Department D ON E.DepartmentId = D.DepartmentId;

Result:

EmployeeName | ManagerName | DepartmentName
-------------+-------------+---------------
Akshay       | NULL        | IT
Rahul        | Akshay      | IT
Amit         | Akshay      | IT
Sneha        | Rahul       | HR

Subquery------>a query inside another query.
---------------------------------------------------------------------------------------------------------
Note -->>UNION करताना प्रत्येक SELECT मध्ये same number of columns and also same name असणे आवश्यक आहे.

1.UNION------>दोन SELECT queries चे results एकत्र करतो आणि duplicate rows काढून टाकतो.
             >UNION combines the results of two or more SELECT queries and removes duplicate rows.

2.UNION ALL-->दोन queries चे results एकत्र करतो, पण duplicates ठेवतो.
             >UNION ALL combines the results of two or more SELECT queries but keeps duplicate rows.
    
* What is differance Join & Union:
                    JOIN = columns combine
                    UNION = rows combine

CTE (Common Table Expression)--->CTE is a temporary named result that we can use inside a SQL query.
                             >CTE म्हणजे query चा temporary result तयार करून त्याला एक नाव देणे आणि नंतर त्या नावाचा वापर करणे.
Synatx:   WITH Something AS (-- complex query ) 
          SELECT column name FROM Something;
------------------------------------------------------------------------------------------------------------
 VIEW ---->is a virtual table created from a SQL query.                          
          >VIEW म्हणजे एका SQL query वर आधारित तयार केलेली virtual table.
Synatx:CREATE VIEW <ViewName> AS
       statement
how to call-->Select * from <ViewName>
Delete View-->DROP VIEW <ViewName>;
Notes----->Don't parametrize the view at all — just filter when you query it.
          VIEW ला arguments/Parameter घेण्याची सोय नसते.

Differance between VIEW & CTE
            CTE ->फक्त त्या SQL statement च्या execution साठी असतो.
                 >Temporary query result--->त्या statement पुरता
            Viwe->तो database मध्ये named view म्हणून save होतो आणि नंतर पुन्हा वापरता येतो:
                 >Saved query definition--->पुन्हा पुन्हा वापरता येतो

Stored Procedure--->Stored Procedure म्हणजे database मध्ये save केलेला SQL code, जो नंतर procedure च्या नावाने पुन्हा execute करता येतो.
syntax:CREATE PROCEDURE GetEmployees
       AS
       BEGIN
           SELECT * FROM Employee;
        END;

How to call------>EXEC GetEmployees;

INDEX----> helps the database find rows faster.
How to call Index---->म्हणजे INDEX = तुम्ही call करत नाही; database optimizer तो automatically वापरू शकतो.
Disadvantage--->Indexes consume storage and can make INSERT, UPDATE, and DELETE
                       operations slower because the index also needs to be maintained.
                >Storage लागते आणि INSERT, UPDATE, DELETE मध्ये overhead वाढू शकतो.
CREATE INDEX --→ INDEX तयार करणे
DROP INDEX ---→ INDEX delete करणे DROP INDEX <Inedex Name>;
Types:
1. Single-Column INDEX --->एका column वर तयार केलेला INDEX.
2. UNIQUE INDEX--Duplicate values allow करू नयेत आणि index देखील हवा असेल तर UNIQUE INDEX वापरू शकतो.
3. Composite INDEX--->एकापेक्षा जास्त columns वर एक INDEX.
5. Partial INDEX---->सर्व rows वर index न बनवता, specific rows वर index बनवायचा असेल तर Partial Index वापरतो.
                     INDEX(Salary) WHERE Salary > 50000 Specific rows
6.Cluster INDEX---->means PRIMARY KEY(Id)   --Unique row identification
